# StudyFlow Backend — Bug & Issue Report (2026-05-11)

Aggregated from 9 parallel code-review agents covering `common_library`, `api_gateway`, `user_service`, `schedule_service`, `homework_service`, `payment_service`, `file_service`, `notification_service`, and cross-cutting concerns.

## Summary

| Severity | Count |
|---|---|
| **Critical** | 17 |
| **High** | 4 |
| **Important / Medium** | 22 |
| **Low** | 7 |

Top themes:
1. **Authorization is broken in multiple services** — IDOR on payment_service (`GetReceipt`, `VerifyReceipt`, `GetReceiptFile`), schedule_service (`MarkAsPaid`, `ListCompletedUnpaidLessons`), homework_service (`CreateAssignment`, `UpdateAssignment`), file_service (`GenerateDownloadURL`, `GetFileMeta`).
2. **Trust boundary at the gateway is hollow** — `x-user-id`/`x-user-role` headers can be injected by external clients on routes that lack `authMiddleware`, and even on protected routes the middleware writes them onto the same mutable `r.Header` it just read.
3. **Documented "lesson parameter precedence" is not implemented** — `CreateLesson` stores nil; no merge with tutor-student pair or tutor defaults at any read.
4. **Notification service is a stub** — consumes Kafka topics but performs zero Telegram delivery.
5. **No retry/CB at the API gateway** — every outbound gRPC call from the gateway is raw, contradicting CLAUDE.md.
6. **PII is logged broadly** — `common_library/logging/interceptor.go` logs full request body + metadata for every RPC across every service; `user_service` and `api_gateway` and `notification_service` independently re-log payloads.
7. **File-ID round-trip never validated** — homework_service, payment_service, and downstream consumers store `file_id` UUIDs without checking existence in `file_service`.

## Critical

### [BUG-001] External clients can forge `X-User-Id` / `X-User-Role` headers
- **Modules:** `api_gateway`, cross-cutting
- **Locations:** `api_gateway/internal/middleware/auth.go:46-47`, `api_gateway/internal/handler/utils.go:74-79`
- **Category:** Auth chain integrity
- **Description:** `authMiddleware` mutates `r.Header` with the validated `X-User-Id`/`X-User-Role` after auth. `Handle()` then reads from `r.Header.Get` to populate gRPC outgoing metadata. Routes registered **without** `authMiddleware` (e.g. `POST /users/sign-up/telegram`, `PUT/GET /files/upload/*`, `/files/download/*`, `/health`) forward whatever headers the caller supplied. No top-level strip of these reserved headers.
- **Fix:** At the very top of the global logging middleware, unconditionally strip `X-User-Id`, `X-User-Role`, and `X-Trace-Id` from every incoming request. Propagate identity via typed context keys (already in `common_library/ctxdata`) and build gRPC metadata from context, not from `r.Header`.

### [BUG-002] Gateway performs zero Telegram HMAC validation
- **Module:** `api_gateway`
- **Location:** `api_gateway/internal/middleware/auth.go:12-51`
- **Category:** Auth — defense in depth
- **Description:** The `Authorization` header is forwarded verbatim to `user_service.AuthorizeByAuthHeader`. The gateway's stated role as the trust boundary is hollow — all crypto verification is delegated downstream, with no timeout/CB on the auth call (request hangs forever if user_service is slow).
- **Fix:** Either perform HMAC validation in the gateway middleware, or add explicit timeout (e.g. 3s) + circuit breaker around the auth gRPC call.

### [BUG-003] MinIO upload/download proxy is unauthenticated
- **Module:** `api_gateway`
- **Location:** `api_gateway/internal/handler/file.go:43-44`
- **Category:** Auth
- **Description:** `PUT /files/upload/*` and `GET /files/download/*` are registered without `authMiddleware`. Anyone can use the gateway to proxy raw S3 ops.
- **Fix:** Apply `authMiddleware` to both routes (or remove them and require clients to use signed URLs directly).

### [BUG-004] Gateway leaks internal auth headers to MinIO
- **Module:** `api_gateway`
- **Location:** `api_gateway/internal/handler/file.go:97-98`
- **Category:** Auth / information disclosure
- **Description:** `req.Header = r.Header.Clone()` copies `Authorization`, `X-User-Id`, `X-User-Role` to the outbound MinIO request.
- **Fix:** Whitelist only `Content-Type`, `Content-Length` on the forwarded request.

### [BUG-005] `file_service.GenerateDownloadURL` and `GetFileMeta` have no ownership check
- **Module:** `file_service`
- **Location:** `file_service/internal/service/service.go:87-102`
- **Category:** Auth — IDOR
- **Description:** Any caller with a `file_id` UUID gets a presigned download URL. No check against `files.uploaded_by` or any ACL.
- **Fix:** Add `caller_user_id` to the request, compare to `file.uploaded_by`, or introduce an explicit ACL table for cross-user reads (homework feedback, payment receipts).

### [BUG-006] `file_service.InitUpload` does not enforce Content-Type on signed PUT
- **Module:** `file_service`
- **Location:** `file_service/internal/service/service.go:130-142`
- **Category:** Content security
- **Description:** `PresignPutObject` is called without `ContentType` in `PutObjectInput`. The signed URL accepts any MIME; a JPG-named upload can hold HTML/JS payload and S3 will serve it back with whatever the client declared.
- **Fix:** Set `ContentType: aws.String(mimeForExtension(ext))` or switch to a presigned POST policy with a content-type condition.

### [BUG-007] No upload confirmation / orphan files accumulate forever
- **Module:** `file_service`
- **Location:** `file_service/internal/service/service.go:60-84`
- **Category:** Resource hygiene
- **Description:** `InitUpload` writes a DB row but there is no `ConfirmUpload` RPC, no `is_uploaded` flag, no TTL cleanup. Other services can attach phantom `file_id`s; `GenerateDownloadURL` returns a URL that 404s.
- **Fix:** Add `is_uploaded BOOLEAN` column + `ConfirmUpload` RPC or periodic cleanup of rows older than signed-URL TTL with `is_uploaded=false`.

### [BUG-008] `payment_service.SubmitPaymentReceipt` allows duplicate receipts on the same lesson
- **Module:** `payment_service`
- **Location:** `payment_service/internal/service/service.go:87-116`
- **Category:** Race / idempotency
- **Description:** `lesson.IsPaid` check → `CreateReceipt` → `MarkAsPaid` are three non-atomic steps. Concurrent submissions both pass the check and both insert receipts. `receipts.lesson_id` has no UNIQUE constraint.
- **Fix:** Add `UNIQUE` on `receipts.lesson_id`, map unique-violation to `ErrAlreadyExists`.

### [BUG-009] `payment_service.VerifyReceipt` is IDOR-vulnerable
- **Module:** `payment_service`
- **Location:** `payment_service/internal/service/service.go:173-179`
- **Category:** Auth — IDOR
- **Description:** Checks caller is *a* tutor, never that the receipt belongs to *that* tutor. Any tutor can verify any other tutor's incoming receipts.
- **Fix:** Fetch the receipt → resolve lesson via schedule_service → confirm `lesson.tutor_id == caller`.

### [BUG-010] `payment_service.GetReceipt` and `GetReceiptFile` have no authz

### [BUG-014] Lesson parameter precedence (lesson > pair > tutor) not implemented

## High

### [BUG-018] No retry / circuit breaker / timeout on any gateway → service gRPC call
- **Module:** `api_gateway`
- **Location:** `api_gateway/internal/handler/utils.go:120`, `client.go:11-32`
- **Category:** Resilience
- **Description:** CLAUDE.md mandates `RetryWithBackoff` + `CircuitBreaker` on every inter-service call. The gateway uses bare `method(ctx, grpcReq)` for all ~30 handler paths. A flaky downstream surfaces as 500 instantly.
- **Fix:** Add unary client interceptor on each `grpc.NewClient` using `common_library/utils`.

### [BUG-019] Auth middleware gRPC call has no timeout
- **Module:** `api_gateway`
- **Location:** `api_gateway/internal/middleware/auth.go:25`
- **Category:** Resilience
- **Description:** `userClient.AuthorizeByAuthHeader(ctx, req)` uses raw request context; slow user_service hangs every request.
- **Fix:** `context.WithTimeout(ctx, 3*time.Second)`.

### [BUG-020] MinIO presigned URL replacement is fragile
- **Module:** `file_service`
- **Location:** `file_service/internal/service/service.go:80`
- **Category:** Correctness
- **Description:** `strings.Replace(url, s.minioURL, gatewayURL, 1)` silently no-ops on prefix mismatch (trailing slash, scheme diff), leaking the internal MinIO URL to the client.
- **Fix:** Use `url.Parse` and rewrite `Scheme`/`Host` explicitly; error if input doesn't match.

### [BUG-021] `homework_service.ReminderWorker` produces duplicate Kafka messages
- **Module:** `homework_service`
- **Location:** `homework_service/cmd/service/worker.go`
- **Category:** Kafka — idempotency
- **Description:** Ticker fires every minute; query is `due_date BETWEEN NOW() AND NOW()+24h`. Same assignment matches up to 1,440 ticks → ~1,440 reminder messages per assignment.
- **Fix:** Track "reminder_sent_at" on assignments, or de-dup downstream, or run hourly with a wider gate.
